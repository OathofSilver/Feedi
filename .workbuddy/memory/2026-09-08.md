# 2026-09-08 · 通知模块自管化（解耦 SSE 生命周期与视图）

## 变更
- `front/src/stores/notification.ts` 重写：SSE 生命周期改由 `watch(auth.isAuthed)` 自管
  - 登录 → 自动 `open()`：拉首屏列表 + 建 SSE + 4s 退避断线重连
  - 登出 → 自动 `close()`：清理连接 + 清未读 + 清列表
  - 新增 `connected` 状态、删除旧的 `start/stop/openPanel`
- `front/src/views/NotificationsView.vue` 改用 `notif.markSeen()` + `notif.ensureList()`
- `front/src/views/FeedView.vue` 移除冗余的 `notif.start()`（store 自身已 watch）
- `onScopeDispose(close)` 兜底 HMR/组件卸载导致的连接泄露

## 验收
- vue-tsc 0 错误
- 无头 puppeteer 跑 `/notifications`（未登录被路由守卫重定向到 /login）无 console 错误
- 后端启动后：登录即可自连 SSE，铃铛红点 + 抽屉列表即时刷新

## 经验
- 跨页面的全局副作用（SSE/WS/轮询）一定要放在 store 的 `watch + onScopeDispose` 里，
  否则依赖某个特定 view 挂载才会启动，登录时机错位即漏触发。
