# 2026-09-07 · 从零搭建 front/ 抖音风格沉浸式前端

## 交付
- 在空 `front/` 目录用 Vite + Vue3 (TS) + Pinia + Vue Router 从零搭建完整前端
- 视觉：抖音沉浸式竖屏 Feed（9:16 满屏 + 右侧互动栏），深浅双主题
- 接入后端：`http://localhost:9000/api/v1`（vite proxy `/api` + `/static`）
- 命令：`npm install` / `npm run dev` / `npm run build`

## 关键文件
- `front/vite.config.ts` — 反向代理
- `front/src/api/http.ts` — 带 token + 401 自动 refresh 重试的统一 fetch 封装
- `front/src/api/demo.ts` — 后端不可达时 Feed/Discover 演示兜底数据
- `front/src/components/feed/VideoSlide.vue` — 单条 9:16 沉浸卡片（cover→video 优雅降级 + 演示占位）
- `front/src/views/FeedView.vue` — 主入口，scroll-snap 满屏竖屏分页 + IntersectionObserver 替代品=scrollTop/clientHeight
- `front/src/stores/theme.ts` — `useThemeStore()` 必须在 main.ts 启动时实例化一次，否则 Login/Discover 等不直接引用该 store 的页面不会应用主题

## 后端对接雷点
1. `latest_time` 单位不一致：latest=ms、following=sec → loader 各自回填
2. 后端**只注册 `/static/avatars`**，play/cover URL 走 `/static/videos|covers` 会404 → VideoSlide 用 `<img>/<video>` onerror + demo 渐变兜底
3. 重复点赞/关注后端返回 500 而非 4xx → 统一 toast 透传 `error`
5. SSE 事件仅含 notification_id → 收到事件后调 `/notification/list` 二次拉取

## 验证
- vue-tsc + vite build 全通过
- 用本机 Chrome + puppeteer-core 跑 headless 截图：Feed 8 slides 渲染、Login form OK、Discover 12 demo cells 渲染、深浅主题切换持久化
- 后端未启动时（api.exe 没跑）也能完整演示沉浸 Feed
